## 1. 产品概述

### 1.1 产品定位

Novel Platform 是一个面向小说作者的内容创作平台，通过AI技术辅助作者进行多项目并行的小说创作。产品专注于解决传统小说创作过程中的效率瓶颈，为作者提供智能化的写作辅助工具。

### 1.2 目标用户

| 用户类型 | 描述 | 核心诉求 |
|----------|------|----------|
| **网络文学作者** | 日更4000-10000字的网文作者 | 快速产出、保持连载节奏、多项目运营 |
| **传统小说作者** | 追求质量的文学创作者 | 构思辅助、世界观管理、角色一致性 |
| **兼职创作者** | 利用业余时间写作的爱好者 | 时间管理、进度追踪、灵感记录 |
| **工作室/团队** | 多人协作创作团队 | 项目管理、分工协作、质量把控 |

### 1.3 产品愿景

> 让每一位作者都能高效、专注地创作出优秀的小说作品

### 1.4 核心价值主张

- **效率提升**: AI辅助写作，日更速度提升3-5倍
- **多项目并行**: 同时管理多个小说项目，灵活切换
- **智能状态管理**: 自动追踪角色、时间线、世界观一致性
- **创作自由**: 保持作者主导权，AI仅作为辅助工具

### 2.2 用户痛点

|------|------|----------|

| **缺乏创作辅助** | 卡文时缺乏有效工具突破瓶颈 | ⭐⭐⭐⭐⭐ |

## 3. 核心功能需求

### 3.1 功能优先级

| 优先级 | 功能模块 | 说明 |
|--------|----------|------|
| P0 | AI对话写作 | 与AI助手对话进行创作 |
| P0 | 多项目管理 | 创建、切换、管理多个小说项目 |
| P0 | 章节进度追踪 | 实时查看各章节写作状态 |
| P1 | 状态文件管理 | 管理/编辑角色、世界观等设定 |
| P1 | 历史记录回溯 | 查看过往创作记录 |
| P2 | 并行章节写作 | 多章节同时进行AI创作 |
| P2 | 导出功能 | 导出为TXT/EPUB/PDF |

### 3.2 功能详细说明

#### 3.2.1 AI对话写作 (P0)

**用户场景**: 作者想要写新章节，通过对话告诉AI创作要求

**功能描述**:
- 提供类似ChatGPT的对话界面
- 支持上下文理解，持续对话
- AI可理解创作要求、风格偏好
- 支持对已写内容进行修改、续写

**用户流程**:
```
1. 进入写作页面
2. 输入创作指令（如"写一章主角觉醒的章节，约3000字"）
3. AI生成内容
4. 用户确认或要求修改
5. 内容保存到对应章节
```

#### 3.2.2 多项目管理 (P0)

**用户场景**: 网文作者同时写3本书，需要在不同项目间切换

**功能描述**:
- 创建新项目，填写项目名称、简介
- 项目列表展示所有项目
- 快速切换当前工作项目
- 项目独立隔离，数据互不干扰

**用户流程**:
```
1. 点击项目选择器
2. 从列表中选择项目或创建新项目
3. 进入项目工作区
4. 查看和管理该项目内容
```

#### 3.2.3 章节进度追踪 (P0)

**用户场景**: 作者需要知道哪些章节已写、哪些待写

**功能描述**:
- 章节列表展示
- 章节状态标识：待写/规划中/写作中/已完成
- 显示章节字数
- 支持章节搜索和筛选

**状态说明**:
| 状态 | 说明 |
|------|------|
| 待写 | 尚未开始写作 |
| 规划中 | 正在构思大纲 |
| 写作中 | AI正在生成内容 |
| 已完成 | 章节已写完 |
| 审核失败 | AI生成内容不符合要求 |

#### 3.2.4 状态文件管理 (P1)

**用户场景**: 作者需要维护角色设定、世界观、时间线等

**功能描述**:
- 状态文件列表
- 在线编辑状态文件
- AI在写作时参考这些设定
- 支持Markdown格式

**核心状态文件**:
| 文件 | 用途 |
|------|------|
| characters.md | 角色档案：姓名、性格、外貌、背景等 |
| timeline.md | 时间线：事件发生顺序和时间点 |
| world_rules.md | 世界观：魔法/科技体系、地理、势力等 |
| glossary.md | 术语表：专有名词解释 |

#### 3.2.5 历史记录回溯 (P1)

**用户场景**: 作者想查看之前的创作记录或找到某个灵感

**功能描述**:
- 对话历史列表
- 按时间排序
- 显示对话预览和消息数量
- 支持搜索历史记录

#### 3.2.6 并行章节写作 (P2)

**用户场景**: 让AI同时写多个章节，提升创作速度

**功能描述**:
- 选择多个待写章节
- 一键启动并行写作
- 实时显示各章节进度
- 写作完成后统一检查

## 4. 产品流程

### 4.1 核心用户旅程

#### 新用户首次使用

```
注册/登录
    ↓
创建第一个小说项目
    ↓
填写项目基础信息（书名、类型、简介）
    ↓
进入项目工作区
    ↓
通过对话开始创作第一章
    ↓
AI生成内容 → 用户确认 → 保存
    ↓
继续创作或退出
```

#### 日常创作流程

```
登录
    ↓
选择要工作的项目
    ↓
查看今日计划/进度
    ↓
选择要写的章节
    ↓
与AI对话进行创作
    ↓
检查生成内容
    ↓
保存或要求修改
    ↓
完成今日目标
```

### 4.2 关键页面流程

#### 项目创建流程

```
点击"新建项目"
    ↓
填写项目信息：
  - 项目名称（必填）
  - 项目简介（选填）
  - 创作类型（选填）
    ↓
确认创建
    ↓
进入新项目工作区
```

#### 章节创作流程

```
选择章节（或新建章节）
    ↓
进入对话界面
    ↓
输入创作要求
    ↓
AI生成内容（实时流式显示）
    ↓
用户查看内容
    ↓
【分支A】满意 → 确认保存
【分支B】不满意 → 要求修改 → 返回AI生成
```

"""Prompt building utilities for Novel Writing Agent.

系统提示词完全固定，不依赖 project_path。
详细协议在 CORE_PROTOCOL.md 中，由 Runtime Context 层动态提供。
"""

import logging

logger = logging.getLogger(__name__)


# ============================================================================
# 固定系统提示词（宪法层）
# ============================================================================

SYSTEM_PROMPT = """你是严格遵循项目协议的小说工程 Agent。

━━━━━━━━━━━━━━━━━━━━━━━━━━
【最高优先级规则】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. ⛔ 一次只能写一章，完成后必须立即停止。
2. ⛔ 没有 outline 禁止写正文。
3. ⛔ 每次操作后必须更新相关 state 文件。
4. ⛔ 写作完成后必须将 cursor.phase 重置为 "idle"。
5. ⛔ 不得绕过状态检查直接执行任务。
6. ⛔ 不得自动继续下一章。
7. ⛔ 不得在完成后主动建议继续。
8. √ 大纲可以连续生成

━━━━━━━━━━━━━━━━━━━━━━━━━━
【核心真相源】
━━━━━━━━━━━━━━━━━━━━━━━━

唯一真相来自以下文件：
- project.yaml
- plan/structure.md
- plan/world_building.md
- plan/characters_guide.md
- volumes/**/chXX_outline.md
- volumes/**/chXX.state
- runtime/cursor.state
- progress/overview.state
- state/*.state

━━━━━━━━━━━━━━━━━━━━━━━━
【强制决策流程】
━━━━━━━━━━━━━━━━━━━━━━━━

1. 若 project.yaml 不存在或 inited != true → 初始化项目
2. 若 plan/ 设计不完整 → 先完成设计
3. 若目标章节无 outline → 生成大纲
4. 若 cursor.phase == "writing" → 继续当前章节
5. 若 cursor.phase == "idle" → 等待合法写作指令

━━━━━━━━━━━━━━━━━━━━━━━━
【写作完成后的强制动作】
━━━━━━━━━━━━━━━━━━━━━━

1. 统计字数并更新 chXX.state.word_count
2. 更新 chXX.state.status = "done"
3. 更新 cursor.state.phase = "idle"
4. 更新 cursor.state.current_chapter 为下一章
5. 更新 progress/overview.state
6. 输出已更新文件清单
7. 立即停止，等待用户指令

━━━━━━━━━━━━━━━━━━━━━━━━
【输出协议】
━━━━━━━━━━━━━━━━━━━━━━━━

成功时必须输出：任务完成确认 + 已更新文件列表
失败时必须输出：无法执行原因 + 当前缺失项 + 下一步建议

违反以上规则必须拒绝执行。"""


def get_system_prompt() -> str:
    """Get fixed system prompt.

    Returns:
        Fixed system prompt string
    """
    return SYSTEM_PROMPT.replace("\n", "")


def build_runtime_context(project_path: str) -> str:
    """Build runtime context layer - Simplified state reading.

    Args:
        project_path: Project path as string

    Returns:
        Runtime context string
    """
    if not project_path:
        return ""

    try:
        from pathlib import Path
        project = Path(project_path)

        context_lines = []

        # Read cursor.state
        cursor_file = project / "runtime" / "cursor.state"
        if cursor_file.exists():
            content = cursor_file.read_text(encoding="utf-8")
            for line in content.strip().split('\n'):
                if line.startswith('phase='):
                    context_lines.append(f"cursor.phase = {line.split('=')[1].strip()}")
                    break
        else:
            context_lines.append("cursor.phase = unknown")

        # Read progress/overview.state
        progress_file = project / "progress" / "overview.state"
        if progress_file.exists():
            content = progress_file.read_text(encoding="utf-8")
            for line in content.strip().split('\n'):
                if line.startswith('completed_chapters'):
                    context_lines.append(f"已完成章节数 = {line.split(':')[1].strip()}")
                    break

        if not context_lines:
            context_lines.append("项目状态：无法读取")

        return "\n".join([
            "━━━━━━━━━━━━━━━━━━━━━━━━━━━━",
            "【当前项目状态】",
            "━━━━━━━━━━━━━━━━━━━━━━━━━━",
            "\n".join(context_lines),
            "",
        ])

    except Exception as e:
        logger.warning(f"Failed to build runtime context: {e}")
        return ""

    """Build clean user prompt - Task Layer.

    只放用户真实请求，不混入规则。

    Args:
        user_message: The user's message

    Returns:
        User prompt string
    """
    return user_message
